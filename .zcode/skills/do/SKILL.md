**Дневной драйвер.** Ученик запускает только `/do`. Команда сама понимает, что делать, и под капотом надевает нужную шляпу: `tutor` (учить/проектировать/адаптировать) или `examiner` (честно проверить, свежий контекст). `/in /plan /go` — алиасы; `/exam` — ручной override (обычно не нужен, `/do` сам решает когда экзаменовать).

## Routing (по первому токену, без угадки)

| Ввод | Режим |
|------|-------|
| первый токен ровно `in` / `plan` / `go` / `exam` | **явный** — остаток = аргумент того скилла |
| есть текст (не зарезерв. слово) | **intake** — новая тема |
| пусто | **«что сегодня»** — драйвер дня |

## Режим «что сегодня» (`/do` без аргумента)

Прочитать состояние: `docs/inbox.md`, активный модуль (`docs/modules/` со `Статус: In progress`), `docs/skill-map.md` (review-due + слабые места), `docs/roadmap.md`, `docs/plans/plans.md`. Решить в порядке приоритета и **сложить план дня одним сообщением**:

1. **Inbox непуст** → разобрать входящее (`in.md`) до остального.
2. **Подошёл повтор (spaced)** → модули, у которых `review-due ≤ сегодня` (meta модуля / skill-map). Предложить/провести повтор — под капотом `examiner` (teach-back + калибровка, см. `exam.md`). Это «что перепроверить сегодня».
3. **Активный модуль** (In progress) → продолжить практику со следующего шага (`go.md`). Когда шаги §6 пройдены и §9 критерий достигнут → **сразу довести до фиксации результата** (deploy: артефакт в `artifacts/` + запись в журнал + Done), подтвердив наблюдаемый критерий. Пользователь не вызывает `/deploy` — `/do` сам закрывает модуль.
4. **Нет активного** → предложить следующий по `roadmap.md` (breadth: другая область; depth: ступень), запустить через `plan`.
5. **Слабое место** в skill-map давно не зондировалось → предложить короткий exam на него.
6. **Всё закрыто** → сказать прямо + предложить новую тему или паузу. Не выдумывать работу.

Барьер-вопрос только при риске (§10 модуля) или ≥3 действиях за заход; иначе вести по плану дня, отмечая прогресс.

## Режим INTAKE (`/do <новая тема>`)

1. **Триаж** (`in.md`): новый модуль / разведка / в roadmap / в бэклог-глубины / ответ. Вердикт строкой. Разведка заканчивается finding'ом, не модулем → **STOP**.
2. **Вплести, не пристроить островом** (ключевое): новая тема ложится в `roadmap.md` **с мостами** — на что из пройденного опирается, что даёт дальше; где её место в порядке. Если активный модуль есть — по умолчанию в roadmap/backlog (one-module rule), явное «давай сейчас» → подтвердить переключение.
3. Исход «build» → `plan.md` (tutor проектирует модуль, читая skill-map, закладывая мосты).

## Роли инициируют сами (ты не помнишь скиллы)

Ты гоняешь `/do`. Когда применить `/page` (интерактив), `/anki` (зубрёжка), проверку (examiner), адаптацию плана — решают `tutor`/`examiner` по конкретным условиям (learning-method.md §9), не ты:
- **Зубрёжка → Anki:** тема — атомы на recall (≥~5 фактов/формул/распиновок), не навык → `tutor` предлагает `/anki`. Не пихать в модуль (мешает practice-first).
- **Визуал → `/page`:** концепт с ≥2 взаимодействующими частями или 2× непонят на словах → `tutor` инициирует интерактивный мок.
- **Проверка:** `review-due ≤ сегодня` или слабое место → `/do` зовёт `examiner` (teach-back + калибровка).

Команды `/page /anki /exam /plan /go /deploy` — ручной override, в норме не нужны. **Пользователь помнит только `/do`** — он сам ведёт весь цикл in→plan→go→deploy и зовёт роли.

## Границы
- `/do` доводит модуль до `/deploy` сам (артефакт+журнал), но артефакт/критерий **подтверждает** с учеником (не молча).
- Не дублирует логику in/plan/go/deploy/exam/anki/page — маршрутизация + сборка плана дня + доведение цикла.
