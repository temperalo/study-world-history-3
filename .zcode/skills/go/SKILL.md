**Practice mode.** Ведёт модуль по шагам: объясняет just-in-time, помогает с затыками, отмечает прогресс. Завершается готовностью к `/deploy` (артефакт).

## Вызов

```
/go docs/modules/<NN>-<slug>.md   один модуль
/go                               конвейер: все Approved по plans.md
```

## Фаза 0 — Gate

1. Прочитать модуль целиком.
2. **Mental-tests gate:** §«Проверка перед практикой» заполнена (5 проверок) + §3 применимый результат задан? Нет → **STOP**: «модуль не прошёл проверку перед практикой, прогони `/plan`».
3. **Материалы:** §4 на руках? Нет → `**Статус:** Blocked` + причина → стоп.
4. **Риск (§10):** если есть — **один** вопрос: «Практика несёт риск: <что>. Меры: <…>. Продолжить? (да/нет)». Без «да» — STOP.
5. Чисто → `**Статус:** In progress`, Фаза 1.

## Фаза 1 — Практика по шагам

Для каждого шага §6 модуля:
1. Сделать/направить шаг. Объяснение **по ходу** (tutor через Task для содержательных разборов; мелкое — main inline).
2. Затык (не запускается / не сходится) → разобрать вместе. **3 failed attempts** одного затыка → **Hypothesis Journal** (workflow.md) → STOP, спросить. Не «чинить вслепую».
   - **Фиксировать трудность:** затык 3 фейла подряд ИЛИ повторное переобъяснение одного и того же → строка в `docs/skill-map.md` «Слабые места» (тема · свидетельство). Это вход для адаптации плана tutor'ом (learning-method.md §8). Не держать «в голове».
3. **Разобрать со мной (§8):** проактивно поднять вопросы понимания из §8 — это не опционально, это метод (learning-method.md §2).
   - **Задействовать мосты (§Мосты):** где модуль опирается на прошлое — реально достать артефакт прошлого модуля и встроить, проговорить связь «как это совмещается с M{k}». Не просто упомянуть — применить.
4. Отметить шаг `[x]` в файле модуля. Записать наблюдения/грабли в §7 по ходу.
5. session-log realtime: `Mode: practice, module <slug>, step i/N`.

## Фаза 2 — К результату

1. Последний шаг → §3 применимый результат достигнут? Проверить по §9 критерию (наблюдаемо).
2. Достигнут → сказать «готов к `/deploy`» (не деплоить молча — deploy фиксирует артефакт + журнал, см. `deploy.md`).
3. Не достигнут, но сессия кончилась → оставить `In progress`, прогресс в файле, session-log. Возобновление в следующий `/go`.

## Конвейер (`/go` без аргумента)

Несколько Approved-модулей подряд. Обычно учёба = один активный модуль, так что конвейер редкий.

### C0 — Reconcile
Скан модулей → `Статус:` каждого. Реестра/архива нет → создать. `Done` → **переместить** строку `plans.md` → `plans-done.md`. `In progress` (прерванный) → трактовать как Approved.

### C1 — Kill-switch (barrier по порогу)
Прогнать Фазу 0 по каждому Approved. **Спросить одним сообщением** только если: Approved-модулей **≥ 3**, или среди них есть риск (§10). Иначе (1–2, без риска) — молча исполнять, лог строкой в session-log.

### C2 — Исполнение (по порядку реестра)
Каждый модуль — Фазы 0–2. `Blocked`/затык → пометить, к следующему. session-log: `Mode: conveyor, module i/N`.

## Правила поведения

- **Тишина до результата** в конвейере; для одиночного модуля — диалог по ходу (это и есть практика, не молчать).
- **Classification не пишем** (skip §2 CLAUDE.md — модуль и есть понимание).
- **Не объявлять готовым без артефакта** — `/go` доводит до результата, фиксирует его `/deploy` (§5 Forbidden CLAUDE.md).
- **Не топить в теории** — just-in-time, ровно под текущий шаг.
- **Session log обязателен** — realtime, не в конце.
- **Honesty:** не уверен в факте по ходу → «нужно проверить», не выдумывать.

## Совместимость с trust level

Practice запускается независимо от trust (вызов skill задаёт режим). Риск (§10) — confirm всегда.
