# Workflow

## Основной поток

**`/do`** — единый фронт `in → plan → go`. Режим по первому токену: `/do <текст>` впустить новое (триаж → план модуля → аппрув → запуск); `/do` (пусто) разгрести `docs/inbox.md` затем доска; `/do in|plan|go [arg]` явный режим. `/in` `/plan` `/go` — алиасы. Под капотом:
- **`/in`** — разбор входа («хочу выучить X» / вопрос из `docs/inbox.md` или inline) → новый модуль / в roadmap / в бэклог-глубины / ответ. tutor проектирует модуль.
- **`/plan`** — поток: построить модуль (tutor) → проверить (5 mental tests + §3 применимый результат) → превью → аппрув одним вопросом → по «да» зовёт `/go`.
- **`/go`** — практика модуля по шагам, диалог-объяснение по ходу (tutor). Конвейер Approved-модулей.
- **`/deploy`** — зафиксировать применимый результат: артефакт в `artifacts/` + запись в `docs/journal.md` + модуль `Done`.

Боковые (по нужде): `/exam` (проверка удержания, examiner), `/journal`, `/status`, `/undo`.

**Branches:** не создавать. Работа в текущей ветке.
**Order:** in (разбор) → plan (модуль + mental tests) → аппрув → go (практика) → deploy (артефакт + журнал) → [позже] exam.
**Workdir:** корень курса (папка, в которой лежит этот CLAUDE.md).
**Modules:** `docs/modules/<id>-<slug>.md`, скелет `_template.md`. Один активный модуль за раз (breadth: следующий после `/deploy`).
**Roadmap:** `docs/roadmap.md` — карта предмета (области/ступени + список модулей с галочками). Не дублирует модули, только обзор.
**Artifacts:** `artifacts/` — реальные результаты (файл/демо/ссылка-фото/код). Модуль не `Done` без записи сюда.
**Backlog (глубина):** «копнуть потом» / off-task → `docs/backlog.md`. Сделал → `[x]`.
**Journal:** после каждого `/deploy` — `docs/journal.md`: дата · собрал · понял · не вышло.
**Commit:** мелкое (заметка, шаг) — сам; крупное — предложить. Format: `study:/fix:/chore:`. Показать diff до commit.
**Done (модуль):** все шаги §6 отмечены + §9 критерий достигнут + артефакт в `artifacts/` + запись в journal + session-log + commit-status.

## Статусы модуля

`Draft / Approved / In progress / Done / Blocked / Cancelled`.
- `/plan` поток ставит: Draft (построение) · Approved (аппрув, после mental tests).
- `/go` ставит: In progress · Done.
- `Blocked` — нет материалов (§4) / нужен пред-модуль. `Cancelled` — правка `**Статус:**` руками.

## Реестр и файлы

```
docs/inbox.md                     ← «хочу выучить» / вопросы (на разбор)
docs/backlog.md                   ← бэклог-ГЛУБИНЫ (копнуть потом)
docs/roadmap.md                   ← карта предмета (области/ступени)
docs/modules/_template.md         ← скелет модуля
docs/modules/<id>-<slug>.md       ← модуль (что/зачем/как слиты)
docs/plans/plans.md               ← реестр активных модулей (порядок = прохождение)
docs/plans/plans-done.md       ← завершённые (Done/Cancelled)
docs/journal.md                   ← лента пройденного
docs/flow.md                      ← индекс воркфлоу (in→plan→go→deploy→exam)
docs/sessions/session_YYMMDD.md   ← session log
artifacts/                        ← применимые результаты
```

## Гейты (что блокирует переход)

- **Approved** требует: §«Проверка перед практикой» заполнена (5 mental tests) + §3 применимый результат + §6 шаги + §9 критерий готовности.
- **`/in`**: вход не уходит без исхода (inbox-пометка `[x]` + строка в `docs/flow.md`).
- **`/deploy`**: модуль не `Done` без артефакта в `artifacts/` + записи в journal. «Понял» без артефакта → не deploy.
- Каждый этап дописывает строку в **`docs/flow.md`** (append как гейт): `<дата> | /<этап> | <модуль> | → <исход>`.

## Modes & kickoff

Крупная новая учебная инициатива в свободном чате (мимо `/do`) — **входящее, проскочившее разбор**. До модуля: назвать режим, впустить через `/do`. Цель — «пул тем → roadmap-блок с мостами → конвейер модулей → уйти», не реактивное «добавь тему → следующую → следующую».
- **Разведка** (учебный spike) — проверка осуществимости до создания модуля: есть ли источники, не нужен ли пред-модуль, реалистичен ли объём. **Пачкой** — сразу список вопросов. Выход: знание, не артефакт и не модуль → finding в `docs/backlog.md` / `docs/roadmap.md` + решение «брать / отложить / заблокировано пред-модулем». Новые вопросы → в inbox на следующую разведку. Из разведки — только через `/plan`.
- **Работа по модулю** (build) — обычный поток `in → plan → go → deploy`.
- **Инициатива ≠ капля.** Много родственных тем — **не плодить модули поодиночке**. Копить в `docs/inbox.md`, затем **один** `/in <блок>` добавляет их в roadmap **с мостами** (что на что опирается, порядок прохождения) → конвейер `/plan → go → deploy` по одному модулю. Реактивный «хочу выучить X сейчас» — только если честно изолированная тема, не часть большой цели.
- **Fork-guard:** запрос нового study-проекта, пока есть активный модуль (In progress) → строка в `docs/inbox.md` + подтверждение. One-module rule расширяется на уровень проектов.

## Self-control

**3 attempts** — затык в практике (не запускается / не сходится) failed 3× → STOP, **Hypothesis Journal** (ниже), спросить. Не «чинить вслепую».
**Loop guard** — 3+ одинаковых действия → STOP, спросить.
**Scope** — не трогать другие модули без approval. Не удалять journal/artifacts без confirm.
**Practice-first:** не объявлять «готово» без §3 артефакта. «Понял» — не критерий (§9 или `/exam`).
**Just-in-time:** теории ровно до сборки. Раздув → `docs/backlog.md` (глубина), не в модуль.
**Honesty guard:** фактический вопрос, не уверен → «неизвестно / нужно проверить», не правдоподобный ответ.
**Cross-session:** читать сегодняшний session-log + git log + активный модуль.
**Post-compact:** снапшот инжектится SessionStart-хуком (`session_start_recover.py`), файл потребляется хуком. По инъекции — заполнить `<!-- ... -->` из git log / недавних правок.
**Auto-memory:** пользователь указал на пропущенный шаг → сохранить feedback ([memory.md](../guides/memory.md)).

## Hypothesis Journal (при 3 failed attempts)

Перед «не получается» — краткий журнал попыток, приложить к запросу:

```
| # | Гипотеза (почему не работает) | Что сделал | Наблюдал | Отсёк |
|---|-------------------------------|-----------|----------|-------|
| 1 | нет питания на пине | померил мультиметром | 0 В | проводка ОК, пин мёртв |
```

Зачем: пользователь видит что уже отсечено, даёт целевую подсказку. Далее — 2 пути: углубить разбор (tutor) или изменить scope (упростить шаг / пометить как Blocked).

## Rules audit (high+ tasks)

После задач effort `high`+ — блок в `docs/.rules-audit.md` (Applied / Skipped / Missed / Conflicts / Wasteful / Gaps). Для `low`/`medium` — не пишем (шум). Stop hook блокирует завершение, если задача была `high`+ и нет audit-записи. Периодически — `/rules-retro`.

## Claude fails log

`docs/claude-fails.md` — append-only.
**Hard trigger:** сообщение начинается с `fail:` (regex `^fail:\s*`) → **обязан** append, без уточнений, подтвердить «записано».
**Auto triggers:** модуль объявлен готовым без артефакта (поймано пользователем); examiner подыграл (пропустил дыру); то же замечание повторно.
Формат: `## YYYY-MM-DD — название`, что произошло, **Должен был:**, **Контекст:**.

## Bash chain execution

- **≤ 5 шагов** — отдельными Bash tool-calls, не chain через `&&`.
- **> 5 шагов** — скриптом `scripts/<name>.py`, запуск `python <path>`.

**Why:** широкие wildcards в allow (`Bash(* && *)`, `Bash(python *)`) ломают защиту от prompt-injection. Только узкие path-based правила. Не предлагать расширение allow широкими паттернами как «решение».

## Protected paths

`docs/journal.md`, `artifacts/**` — не удалять/перезаписывать без явного confirm пользователя (это история обучения, восстановить нельзя).
