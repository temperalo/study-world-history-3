# Skill costs — when to use haiku / sonnet / opus

> Каждый skill и subagent имеет `model:` во frontmatter. Этот файл — правило как эту модель выбирать. **Effort и model — ортогональны.**

## Главное правило (default)

**Default — sonnet** для всех ролей где нужно суждение (tutor — объяснить/спроектировать модуль/расшевелить, examiner — проверить удержание). **Haiku** — только для механики (status, journal, undo, cleanup). **Opus — НЕ дефолт**: подключается только при явном запросе пользователя (`use opus`, `через opus`, `--opus`). Иначе быстро сжирает usage.

| Модель | Когда | Почему |
|--------|-------|--------|
| **haiku** | Детерминированная трансформация (вход → фиксированный выход) | Дёшево, быстро, суждение не нужно |
| **sonnet** | Default. Работа по шаблону + любые задачи требующие суждения | Хороший баланс качества и стоимости |
| **opus** | **Только по явному запросу пользователя** для разбора сложной темы / каверзного экзамена | Дорого; включается вручную |

## Примеры (study)

| Задача | Модель | Почему |
|--------|--------|--------|
| Status (доска модулей, что Done) | haiku | Механика, чтение состояния |
| Journal (запись после `/deploy`: дата · собрал · понял) | haiku | Фиксированный формат |
| Undo (откат последнего шага) | haiku | Механика |
| Cleanup (снять отметки, привести модуль к шаблону) | haiku | Grep + правки |
| tutor — объяснить just-in-time / расшевелить в `/go` | sonnet (opus — по явному запросу) | Суждение, диалог по теме |
| tutor — спроектировать модуль (цель/теория/практика/шаги/mental tests) | sonnet | Дизайн модуля = суждение |
| examiner — проверить удержание по завершённым модулям | sonnet (opus — по явному запросу) | Скептик, свежий контекст |
| `/in` разбор входа (модуль / roadmap / бэклог / ответ) | sonnet | Триаж со смыслом |
| `/do` фронт (in→plan→go), оркестрация ролей | sonnet | Оркестратор + subagents все на sonnet |

## Effort ⊥ Model

- **Effort** = сколько процессных шагов (разовый ответ? один модуль? roadmap? capstone?). Управляется §1.3 в CLAUDE.md.
- **Model** = какой мозг на каждом шаге. Управляется этим файлом.

Комбинации валидны все:

| Effort + Model | Когда бывает |
|----------------|--------------|
| `low` + `haiku` | Status доски, одна запись в журнал |
| `low` + `opus` | Только если пользователь явно попросил («объясни этот резонанс на opus») |
| `high` + `haiku` | Массовый cleanup модулей под шаблон (grep-based) |
| `high` + `sonnet` | Roadmap предмета + проектирование модулей: tutor + examiner — всё на sonnet |
| `high` + `opus` | Каверзный capstone-экзамен или разбор сложной темы, пользователь явно попросил |

## Escalation

Если haiku-skill отвечает «не уверен» / «пограничный случай» — эскалация на sonnet. **На opus не эскалируем автоматически** — это только по запросу пользователя.

## Deescalation

Если задача реально механическая (только запись в журнал по готовому формату, или статус доски модулей) — деэскалировать sonnet → haiku. Упоминаем в итоговом ответе.

## Override (как включить opus)

Opus подключается **только** если пользователь явно сказал в запросе: `используй opus`, `через opus`, `--opus`, «экзамен на opus». Тогда соответствующая роль (tutor / examiner) получает opus на эту задачу. Без явной просьбы — sonnet, всегда.
