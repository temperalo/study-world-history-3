# Fact-checking — контроль фактов (анти-галлюцинации)

> Читается при подготовке/проверке контентного артефакта (модуль, шпаргалка, скрипт лекции, страница, колода).
> Цель: ученик **никогда не заучивает непроверенное**; любой факт он может проверить сам за 2 минуты.
> Проверка ≠ самооценка: tutor не верифицирует себя — проверяет независимый `checker` через `/fact-check`.

## 1. Якоря фактов

**Якорь = логический блок**: сущность → утверждения → ссылки/источники → статус уверенности → вердикт чекера с датой.

```markdown
## A-NN · <сущность: событие/компонент/закон/правило>
Утверждения: (а) … ← где в тексте · (б) … ← где в тексте
Статус: ✅ общепринято | ⚠️ наука/практика обсуждает | 💭 интерпретация/правило большого пальца
Ссылки: [первоисточник | книга+глава | даташит/норматив | поисковый ключ]
Вердикт чекера: подтверждено | исправить на «…» | UNVERIFIED — <дата>
```

**Где живут:** рядом с артефактом — `<артефакт>.anchors.md`; для модулей — секция «Реперные точки» в самом модуле. Шаблон — `docs/anchors/_template.md`.

**Правила блоков:**
- Сильное утверждение (точная дата/число/номинал/«первый-самый») — **≥2 независимых источника**.
- ⚠️/💭 обязаны иметь **языковые маркеры в самом тексте** («учёные спорят», «по одной из версий», «правило большого пальца») — без маркера ученик примет гипотезу за факт.
- Непроверяемое — честный **UNVERIFIED**, никогда не «наверное правда».
- Каждый блок подписан датой проверки и вердиктом.

**Цепочки «причина → следствие» — якоря первого класса.** Ядро объяснения в любом предмете — цепочка (история: «излишки → государство»; электроника: «рост R → падение тока»; химия: «блок фермента → накопление субстрата»). Красивая цепочка ≠ установленная причинность: каждое сильное звено проверяется отдельно — причина установлена или это модель/упрощение (и тогда в тексте обязательны маркер + условия применимости). Цепочка-якорь:

```markdown
## A-NN · Цепочка: A → B → C
Звенья: (а) A→B — <установленная причина | модель, работает при <условиях>> ← где в тексте · (б) B→C — …
Статус: <✅|⚠️|💭> — для модели обязателен маркер в тексте («это упрощение», «работает при …»)
Ссылки: <первоисточник | учебник+глава | поисковый ключ>
Вердикт чекера: <подтверждено | исправить на «…» | UNVERIFIED> — <дата>
```

## 2. Красные флаги (без чека не использовать)

| Флаг | Почему опасен |
|------|---------------|
| «первый / самый / рекорд / единственный» | чаще всего «первое документированное, кем?» — а не «первый вообще» |
| Точная дата/число без вилки | датировки древности — вилки; точечная цифра = красный флаг |
| «N тыс. лет назад» vs «N до н.э.» | ловушка направления отсчёта (ошибка уже ловилась: 4,2 тыс. лет назад = ~2200 до н.э.) |
| «все / всегда / никогда» | универсальные кванторы почти всегда ложны |
| Дословная цитата | проверять точную формулировку + источник, не «пересказ по памяти» |
| Сильная причинная связка «A привело к B» | красивая модель ≠ установленная причина → 💭 с маркером |
| Номиналы/параметры компонентов | max rating ≠ рабочая точка; только по даташиту |
| Единицы и порядки (мА/А, мкФ/нФ) | проверять порядок на здравый смысл |
| Названия/границы/редакции | Русь≠Россия, Византия≠Ромея; НПА — только актуальная редакция |

## 3. Ловушки формулировок

- **Направление отсчёта** — «X тысяч лет назад» ≠ «X лет до н.э.».
- **Единицы** — мА/А, мкФ/нФ/пФ, кВт/Вт: порядок величин сверять со здравым смыслом.
- **Смены имён/юрисдикций** — сущность без анахроничного названия.
- **Идеальный vs реальный компонент** — формула без ESR/допусков/дрейфа = модель, не реальность.
- **Бытовые аналогии** — «ток течёт как вода» без рамки «аналогия кончается здесь» становится заблуждением.

## 4. Иерархии источников по доменам

| Домен | Первоисточник | Далее | Не источник |
|-------|---------------|-------|-------------|
| история | научный консенсус/обзоры | академические учебники (Scarre, Крамер, Wilkinson) → энциклопедия как указатель | научпоп как доказательство |
| электроника | даташит производителя | нормативы (ПУЭ, ГОСТ) → справочники (Хоровиц-Хилл, ТОЭ) | «так на форуме» |
| физика | учебник/справочник (величины, размерности) | экспериментальные обзоры, NIST-таблицы | популярные пересказы |
| право/норматив | текст НПА в актуальной редакции | официальные разъяснения/судебная практика | пересказы статей |
| программирование | официальная документация/стандарт | исходники, RFC/PEP | устаревшие туториалы (версии!) |

Правила: английский поисковый ключ находит больше; один источник на сильное утверждение = пометка «по одному источнику»; форумы и научпоп — указатель для поиска, не подтверждение.

## 5. Workflow кросс-чека — две точки

**1. Пре-чек — до обучения (в `/plan`).** План модуля предсказывает лекцию, поэтому ядро проверяем заранее, а не после обсуждения. checker верифицирует то, что гарантированно прозвучит на первой сессии: крючок-парадокс, мини-теорию (§2 модуля), ключевые факты первого шага (даты/числа/параметры/формулы), **цепочки причин-следствий** (по звеньям). Якоря → «Реперные точки» модуля. Гейт: фактологический модуль без пре-чека не апрувится в `Approved` (§6). Мягкие модули (§8) — пре-чек не нужен. Типовой пре-чек = 3–7 web-запросов, минуты — старту не мешает.

**2. Пост-чек — артефакт перед `/deploy`.** Пре-чек не отменяет: пост-чек проверяет то, чего пре-чек не видел, — **собственный free recall ученика** (ошибка ученика — отдельный сигнал, ловим до Anki) и **импровизацию диалога** (ответы на вопросы, примеры, боковые факты — предсказать их нельзя). Tutor при подготовке контента помечает рискованные места (`⚠️?` в черновике) и зовёт `/fact-check` до `/deploy`.

Механика checker'а (обе точки одинакова): извлечь кандидатов по красным флагам → сгруппировать в якоря-блоки (цепочки — по звеньям) → верифицировать (2–3 запроса в разных формулировках; ≥2 источника на сильное; первоисточник домена обязателен) → записать якоря + вернуть вердикт.
Расхождение → правка текста с источником; ошибка — в `docs/lecture-log.md`. Вердикт: `verified N | fixed N | unverified N` — в lecture-log.

Проверяем **по риску, не всё**: большой артефакт → top-риска сначала, хвост — явным списком непроверенного. Типовой чек = 3–7 web-запросов, минуты.

## 6. Гейты

- **/plan**: фактологический модуль без пре-чека ядра (якорей в «Реперных точках» нет) **не апрувится** в `Approved` — ученик не должен впервые услышать непроверенное на сессии.
- **/deploy**: контентный артефакт с рискованными фактами без якорей и вердикта чекера **не публикуется** (Draft). Исключение — публикация с явной пометкой UNVERIFIED в тексте + записью в lecture-log.
- **/anki**: карты — только из фактов ✅ (или ⚠️ в формулировке «спорно: …»); UNVERIFIED и 💭-риторика в карты не попадают. Нет якорей у модуля → сначала `/fact-check`, потом `/anki`.
- **/exam**: examiner сверяет ответы с якорями артефактов, не с памятью модели; «заученный глюк» → правка якоря/контента, не минус ученику.

## 7. Ошибки фиксируются, не прячутся

`docs/lecture-log.md` — журнал лекций/выпусков: создано / проверка фактов (что найдено) / фидбек ученика / выводы для следующих. Найденная чекером ошибка — **успех системы**, метрика качества, не стыд. Выводы из журнала читает tutor перед следующей лекцией (First operation).

## 8. Домены-исключения (мягкие курсы)

Часть предметов слабо фактологична (гитара, общение, продуктивность): якорь = **техника/упражнение/цитата методики с указанием методика-источника**. Чекер проверяет «техника существует и так ли применяется», а не даты. Не превращать мягкий курс в бюрократию: якоря — для того, что ученик будет заучивать, повторять или рассказывать другим.

## 9. Безопасность

Опасные для жизни темы (электробезопасность, LiPo, химия, медицина): **двойная проверка нормативом** — «подтверждено нормативом» или UNVERIFIED, третьего нет; UNVERIFIED к публикации запрещён.
