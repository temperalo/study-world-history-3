## Когда (решает tutor сам, не команда пользователя)

Пользователь **не вызывает** `/page` и не помнит про него — `tutor` сам инициирует во время `/go`/`/do`, когда срабатывает **конкретное условие**:

- Концепт **визуальный/пространственный с ≥2 взаимодействующими частями**, где «покрутить» бьёт текст: схема/цепь (555), геометрия (overhang, fit), график зависимости (R/C→частота), процесс по шагам, framework на ≥3 варианта («три этические линзы», корзины желаний).
- Ученик **дважды не понял на словах** один и тот же концепт (из диалога/skill-map) → визуал как другой канал (dual coding).
- Явная просьба пользователя («покажи / визуализируй») — но это не основной путь.

**Лучше всего после productive-failure** — сначала попробовал сам, потом крутишь интерактив. Не лекцией вперёд практики. **Не на каждый модуль** — только по условию выше (иначе bloat + пассивное чтение). Для мягких тем (философия/общение) — обычно НЕ нужно, диалог сильнее.

## Что генерит

**Интерактивный**, не статичная картинка с текстом:
- Манипулируемые элементы: слайдеры (R/C → частота), тогглы (вкл/выкл узел), drag, пошаговый раскрыв, переключение состояний.
- Где уместно — **встроенный self-check**: 1–2 вопроса с проверкой (но это не замена `/exam` — там examiner).
- Минимум текста, максимум «потрогать и увидеть результат».

**Технически:** один самодостаточный `.html` файл — inline CSS/JS, **без внешних зависимостей/CDN** (работает офлайн, надёжно). Vanilla JS. Открывается двойным кликом.

## Куда

`pages/<slug>.html` (корень проекта). Связать с модулем по имени (`pages/01-<slug>.html`). Существующий — обновлять (Edit), не плодить дубли.

## Роль (важно)

- Это **учебное пособие**, **не applied-result**. Артефакт `/deploy` — то, что делаешь **ты** (practice-first незыблем). Страница помогает понять, не заменяет практику.
- Не фронт-лоадить теорию: интерактив идёт в связке с попыткой/практикой, не вместо.

## Правила
- **Не выдумывать факты/формулы** — только проверенное из модуля/источника. Не уверен → не визуализировать как факт.
- Самодостаточный HTML, офлайн, без CDN.
- Интерактив должен реально что-то менять (манипуляция → видимый результат), иначе это просто текст в рамке.
- Для мягких тем (философия/общение) — интерактив = прогнать свой случай через framework, а не анимация ради анимации; если визуал не добавляет — честно сказать «тут лучше диалогом», не делать страницу для галочки.
