Единый поток: построить модуль → проверить гейт → превью → **один** аппрув → запуск.

## Вызов

```
/plan <тема | slug модуля>   построить/довести модуль
/plan                        реестр активных модулей + статусы
```

## Поток

**A — Построить.** Делегировать `tutor` (Task): спроектировать модуль по скелету `docs/modules/_template.md` — цель · мини-теория (just-in-time) · **применимый результат (§3)** · что нужно · шаги по сессиям · грабли · разобрать со мной · критерий готовности. tutor **первым делом читает `docs/skill-map.md`** и адаптирует под слабые места (мельче шаги / review / больше диалога / усилить мост — learning-method.md §8), фиксирует адаптацию. Записать в `docs/modules/<NN>-<slug>.md`, `**Статус:** Draft`.

**B — Пре-факт-чек ядра.** Для фактологических модулей (есть «Реперные точки») — `/fact-check --pre <модуль>` (checker, Task): крючок, мини-теория (§2), ключевые факты шага 1, цепочки причин-следствий — до того, как ученик впервые их услышит. Без пре-чека — нет `Approved` (мягкие модули без заучиваемых фактов — пропуск, fact-checking.md §5/§8).

**C — Проверить гейт (mental tests).** Заполнить §«Проверка перед практикой» — 5 проверок:
1. Реальная практика? (§3 артефакт есть, не «кивнул»)
2. Готовность наблюдаема? (§9 проверяем извне)
3. Есть чем делать? (§4 на руках) — нет → `Blocked`, стоп
4. Теория just-in-time? (§2 минимум; раздув → backlog)
5. Применю потом? (повторю через неделю)

Любой «нет» → пересмотреть модуль или `Blocked`/backlog. **Без заполненного блока — нет `Approved`.**

**Гейт связности:** §«Мосты» заполнен — если есть хоть один `Done`-модуль, нужен ≥1 мост «опирается на» (понимание + по возможности реальный артефакт прошлого модуля). Островок без связей → вернуть на доработку или поставить раньше пред-модуль. Самый первый модуль проекта — исключение. tutor закладывает мосты при проектировании (A).

**D — Превью + аппрув.** Показать одним сообщением: цель, применимый результат, шаги (порядок), что нужно, оценка сессий. **Один** вопрос:
- `да` → `**Статус:** Approved` + `**Authority:** carte-blanche` + сразу `/go`;
- `аппрув` → `Approved` + `pre-approve-only`, запуск позже;
- `нет` → остаётся `Draft`.

**E — Реестр.** Добавить/обновить строку в `docs/plans/plans.md`. **Flow (gate):** `<дата> | /plan | <модуль> | → <статус>`.

## `/plan` без аргумента

Реестр активных модулей из `plans.md` + статус каждого (читать `**Статус:**` в файле модуля). Подсветить `Blocked` (что мешает). Не запускать — только показать.

## `/plan <slug>` на существующем

Модуль уже есть (Draft) → сразу шаг B (пре-чек + mental tests).

## Правила

- Проектирует `tutor` (opus, frontmatter), не main (Task для medium+). Task fail → main строит сам в simplified mode, пометить в session-log.
- Подрежимов нет: проверка всегда внутри (B), статус = `/plan` без аргумента, аппрув — в потоке (C).
- §3 применимый результат, §«Проверка» и пре-чек ядра — **жёсткие гейты**. Чисто теоретический модуль не апрувится.
- Один активный модуль (one-module rule из `in.md`). Новый Approved при незавершённом активном — подтвердить переключение.
