## Контракт

В учёбе «deploy» = **реальный применимый результат**, а не git-релиз. Модуль не `Done`, пока нет осязаемого артефакта + записи в журнал. Это защита от «учил-учил, показать нечего».

Sequential: **0 Verify → 1 Artifact → 2 Journal → 3 Done → 4 Next**. Любой fail = STOP + краткий отчёт.

## Вызов

```
/deploy                       активный In-progress модуль
/deploy docs/modules/<NN>-…   конкретный
```

## 0 — Verify (gate)

Прочитать модуль. Проверить:
- §6 шаги все `[x]`? Нет → **STOP**: «модуль не пройден, остались шаги: <…>. Закончи `/go`».
- §9 критерий готовности достигнут **наблюдаемо** (работает / проходит / объясняю без подсказки)? Расплывчатое «вроде понял» — **не** проходит. Спросить пользователя подтверждение наблюдаемого признака.
- §3 применимый результат существует физически?
- **Факт-гейт (контентные артефакты):** артефакт несёт рискованные факты (даты, числа, «первый/самый», формулы, параметры, безопасность)? Тогда нужны якоря (`<артефакт>.anchors.md` / §«Реперные точки») + чекер-вердикт `verified|fixed`. Нет → **STOP**: «контент без проверки фактов = Draft. Прогони `/fact-check`» (или явно пометить UNVERIFIED в тексте + запись в lecture-log — fact-checking.md §6).

Не подтверждено → STOP, не деплоить.

## 1 — Artifact (обязательно)

Зафиксировать осязаемый результат в `artifacts/<NN>-<slug>/`:
- **Код/файл/текст** → положить файл(ы) в папку.
- **Физический результат** (схема, прибор, рисунок, действие) → ссылка на фото/видео + короткое описание `result.md` в папке.
- **Навык-действие** (играю гамму, держу диалог) → короткая запись-свидетельство (что именно сделано, как проверено) в `result.md`.

**Нет артефакта = нет deploy.** Если зафиксировать нечего — модуль не был practice-first, вернуть в `/plan` (mental test #1 провален задним числом).

## 2 — Journal

Append в `docs/journal.md` (сверху): дата · что собрал · что понял (1–2 фразы сути) · что не вышло / грабли · ссылка на `artifacts/<NN>-<slug>/`.

**Контентный выпуск/лекция** (если ведётся `docs/lecture-log.md`): запись туда же по формату шапки — Создано / Проверка фактов (вердикт чекера, найденные ошибки) / Фидбек ученика / Выводы для следующих.

**Разговорный набор (контентные артефакты; мягкие курсы — опц.):** приложить к артефакту секцию «Разговорный слой» по рамке learning-method.md §«Разговорный слой»: 2 хука-парадокса (60-секундная застольная версия) · 1 вопрос собеседнику «как думаешь, почему…?» · 1 микро-объяснение на 60 секунд («расскажи сам», без терминов) · для практических курсов — «покажи-расскажи» (что из собранного показать и как объяснить). Генерирует main по рамке (у скилла нет Task); тон — любопытство, не лекция.

## 3 — Done

- В файле модуля: `**Статус:** Done`, `**Артефакт:** artifacts/<NN>-<slug>/`, `**completedAt:** <дата>`, `**review-due:** <дата+1д>` (старт интервального повтора, см. learning-method.md §4).
- **Reconcile:** переместить строку модуля из `docs/plans/plans.md` в `docs/plans/plans-done.md`.
- `docs/roadmap.md`: отметить модуль ☑, обновить «модулей X/N · областей X/M».
- **Flow (gate):** `<дата> | /deploy | <модуль> | → Done, artifacts/<NN>-<slug>/`.
- Commit (`study: M{n} done — <slug>`), показать diff.

## 4 — Next

- **Сигнал в skill-map:** если модуль дался **тяжело** (много затыков по `flow`/session-log) или **легко** — строкой в `docs/skill-map.md` (Слабые/Сильные). Тяжёлый модуль → пункт в «Открытые корректировки» для tutor.
- Подсветить следующий по `roadmap.md` (breadth: другая область; depth: следующая ступень).
- Предложить (не запускать): «Следующий — M{n+1} <…>. Запустить `/in`? Или `/exam` по пройденному?»
- **Spaced reminder:** если ≥ 3 модулей `Done` и давно не было `/exam` — мягко предложить проверку удержания.

## Report

```
✅ Модуль M{n} <slug> — Done

Применимый результат: <что работает>
Артефакт: artifacts/<NN>-<slug>/
Журнал: записан
Прогресс: модулей X/N · областей X/M

Дальше: M{n+1} <…>  ·  или /exam по пройденному
```

При STOP:
```
❌ Deploy остановлен на фазе <N>
Причина: <шаги не пройдены | критерий не достигнут | нет артефакта | факт-гейт: нет якорей/вердикта checker>
Что делать: <конкретно>
```

## Правила

- **Никогда не Done без артефакта + журнала.** Это весь смысл скилла.
- **Не принимать «понял» за готовность** — нужен наблюдаемый §9 или артефакт.
- **Не удалять/перезаписывать** прошлые артефакты и журнал (история обучения).
- Commit без `--no-verify`. Незавершённые маркеры (`[TODO]`/`TK`) в модуле → не коммитить.
