## Контракт

`/exam` проверяет, что пройденное **осталось и применимо**, а не забылось. Делегирует роли `examiner` (Task) — **намеренно отдельной от tutor**: tutor помогает, examiner проверяет. Свежий контекст экзаменатора = не подыгрывает, не подсказывает ответ в вопросе.

Это реализация mental test #5 («применю потом») и принципа «проверка ≠ самооценка» (learning-method.md §4).

## Вызов

```
/exam                       spaced: поднять модуль(и) Done, давно не проверявшиеся
/exam M{n} | <slug>         конкретный завершённый модуль
/exam all                   все завершённые (длинная сессия)
```

## Выбор цели (`/exam` без аргумента)

1. Прочитать `Done`-модули + их meta (`review-due`, `review-count`, `examined`).
2. **Spaced:** поднять модули, у которых `review-due ≤ сегодня` (срок повтора подошёл). Приоритет — самый просроченный. Обычно `/exam` дёргается автоматически из `/do` («что сегодня»), не руками.
3. Взять 1–2 модуля за заход (не утомлять).

## Пересчёт интервала (после проверки)

Интервалы: **+1д → +3д → +7д → +21д → +60д**. В файле модуля:
- **Держит** → `review-count++`, `review-due` = сегодня + интервал[review-count]; `examined: <дата> · ok`.
- **Дыра/partial** → сброс: `review-count = 0`, `review-due = сегодня+1д`; `examined: <дата> · gaps`.

## Процесс

Делегировать `examiner` (Task, opus — frontmatter), передать: файл(ы) модуля + соответствующие записи журнала + **якоря артефактов модуля** (`<артефакт>.anchors.md` / §«Реперные точки»), если есть. examiner:
1. Разминка — интерливинг: быстрые вопросы из разных прошлых тем вперемешку.
2. Формирует вопросы по §1 цель / §2 теория / §3 практика / §8 «разобрать со мной» завершённого модуля + **§«3 вопроса ученика»** (если заполнена).
3. Задаёт **по одному**, ждёт ответ пользователя, не раскрывая решение вперёд.
4. Оценивает честно: понял суть / поверхностно / дыра. Не засчитывает «вспомнил слово» за понимание. Эталоны — **по якорям**, не по памяти модели: «ученик ответил как в тексте, но текст был глюком» → дыра якоря, правка контента через `/fact-check`, не минус ученику.
5. Где уместно — **прикладная** проверка: «собери заново по памяти X» / «применил бы это к Y как?».

## Исход

- **Держит** → в файле модуля `examined: <дата> · ok`. Flow: `<дата> | /exam | <модуль> | → retained`. skill-map: тема в «Сильные».
- **Дыры** → по выбору:
  - мелкая → заметка в `docs/backlog.md` («повторить <тема>»);
  - крупная → предложить **review-модуль** (короткий, через `/in` → `/plan`) на провисший кусок.
  - В файле модуля: `examined: <дата> · gaps: <что>`.
- **Обновить `docs/skill-map.md`** (gate): перенести «Сигнал для skill-map» из вердикта examiner'а — провисшее в «Слабые места» (с адаптацией), усвоенное в «Сильные», и при review-needed добавить пункт в «Открытые корректировки». Это вход для tutor при следующем `/plan`.
- Flow-строка обязательна (gate).

## Return format (examiner → main)

```
## Exam: M{n} <slug>
Проверено: <темы>
Держит: <что усвоено>
Дыры: <что провисло / нет>
Вердикт: retained | partial | review-needed
Рекомендация: <backlog-заметка | review-модуль | ничего>
```

## Правила

- **examiner ≠ tutor.** Не сливать роли. Экзаменатор не объясняет в процессе проверки (объяснение — потом, если всплыла дыра, уже tutor).
- **Не подыгрывать** (Forbidden CLAUDE.md §5): не давать ответ в формулировке вопроса, не принимать «да помню» без проверки.
- **Не наказывать** — дыра это норма, исход = направление (review/backlog), не оценка.
- Только завершённые (`Done`) модули. Незавершённый экзаменовать нечего.
